# Glossary

Pomodash 도메인 용어 정의. 코드/문서에서 쓰는 내부 모델명과, 사용자가 화면에서 실제로 보는 UI 카피가 다른 경우가 있어 이를 명시적으로 구분한다.

## 개념 계층

```
작업(Task)  ──[시작]──▶  세션(Session)  ──[구성]──▶  사이클(Cycle)  ──[구성]──▶  페이즈(Phase)
 "무엇을 할지" 계획         "한 번 실행한 기록"          "집중+휴식 1쌍"          "집중" 또는 "짧은휴식"
```

| 개념 | 정의 | 코드 대응 |
|---|---|---|
| 작업 (Task) | 앞으로 할 일에 대한 계획/템플릿. 목표 시간·사이클 수만 가짐, 실행 이력은 없음 | `Task` |
| 세션 (Session) | 작업을 골라 타이머를 실제로 돌린 한 번의 실행 기록. 시작/종료 시각, 실제 집중 시간, 완료 사이클, 회고 메모 등 "일어난 일" 데이터 | `Session` |
| 사이클 (Cycle) | 세션 내부의 반복 단위. 집중 → 짧은휴식 1쌍. `totalCycles`번 끝나면 세션 종료 | Session에 내장, 별도 타입 없음 |
| 페이즈 (Phase) | 사이클을 이루는 두 상태: `focus`(집중) / `short-break`(짧은휴식) | `TimerPhase` |
| 집중구간 (FocusPeriod) | 세션 중 일시정지 없이 실제로 집중한 시간 블록. 타임라인 시각화용 | `FocusPeriod[]` |
| 저널 (Journal) | 지난 세션들을 캘린더/리스트로 모아보고 인사이트를 확인하는 화면 | `components/journal/Journal*` |
| 대시보드 (Dashboard) | 세션들을 집계한 차트/스트릭/뱃지 화면 | `components/dashboard/*` |

## UI 카피 규칙 — "세션"은 화면에 노출하지 않는다

내부적으로는 `Session`이 정확한 모델명이지만, 사용자에게 "세션"이라는 외래어를 그대로 보여주면 처음 쓰는 사람은 의미를 유추하기 어렵다. UI 카피에서는 문맥에 따라 아래 두 단어로 나눠 쓴다.

| 문맥 | 사용 단어 | 예시 |
|---|---|---|
| 진행 중 (action) — 타이머를 시작/설정/종료하는 시점 | **타이머** | "타이머 시작", "타이머를 종료할까요?", "이번 타이머 설정" |
| 완료 후 (entity) — 저장되어 조회되는 데이터 | **기록** | "N개의 기록", "기록 상세", "아직 기록이 없어요" |

- 저널 페이지의 하단 탭 라벨이 이미 "기록"이라, 완료된 세션을 "기록"이라 부르는 것과 자연스럽게 맞아떨어진다.
- 사이클/집중/휴식은 이미 직관적인 단어라 별도 치환 없이 그대로 쓴다.
- 코드 식별자(`Session` 타입, `sessionStore`, `sessions` 테이블, `SessionRecordModal` 같은 컴포넌트명)는 **그대로 유지**한다 — 개발자 문서와 코드에서는 "Session"이 정확하고 검색 가능해야 하므로 UI 카피 규칙과 별개로 다룬다.

## 문서별 적용 범위

| 문서 | "세션" 표기 |
|---|---|
| `data-models.md`, `ERD.md`, `architecture-diagram.md`, `conventions.md`, `testing.md`, `commit-convention.md`, `CLAUDE.md` | 코드 모델명 그대로 사용 (정확함, 변경 안 함) |
| `PRD.md`, `feature-spec.md`, `screen-spec.md`, `design.md` | 사용자 화면 문구를 설명하는 부분은 위 UI 카피 규칙을 따름 (타이머/기록으로 표기) |
